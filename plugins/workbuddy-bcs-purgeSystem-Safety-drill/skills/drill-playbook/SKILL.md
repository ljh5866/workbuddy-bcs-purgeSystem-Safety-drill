# 演练手册

常驻规范在 `rules/spec.md`（输出形态与档位）。本手册补的是演练的流程、证据与交付物结构。

## 六阶段

| 阶段 | 产出物 | 退出条件 |
| --- | --- | --- |
| 清点 | 资产清单、指纹表、面图 | 每个入口有指纹与版本，标了置信度 |
| 验证 | 可复现条目（请求 / 响应 / 时间戳） | 至少一条稳定复现，或记全失败路径 |
| 立足 | 会话凭据、驻留点清单 | 拿到可用会话或等价访问，记存活时间 |
| 横向 | 可达主机图、凭据复用矩阵 | 画出从入口到目标资产的最短路径 |
| 取证 | 证据目录 | 每条结论都挂一个证据文件 |
| 报告 | 报告正文 | 非技术读者能读懂等级与影响 |

## 证据纪律

形态：命令 + 完整输出、HTTP 原文 + 响应头尾、截图 + 时间戳、文件哈希。

未验证的结论写「推测」并注明依据；报告里已证实与推测分两栏，不混写。

命名：`<阶段>-<序号>-<短描述>.<扩展名>`，例如 `02-03-sqli-boolean-blind.txt`。

## 报告骨架

```markdown
# 演练报告 · TARGET · YYYY-MM-DD

## 执行摘要
三句话：打到哪、拿到什么、最严重的风险是什么。

## 范围
目标清单、时间窗口、排除项。

## 路径
入口 → 逐跳 → 目标资产。每跳一行：`HOST:PORT [手法] → 下一跳`。

## 发现
### F-01 标题
- 等级：严重 / 高 / 中 / 低
- 位置：URL / 文件 / 服务
- 复现：最小步骤
- 证据：`evidence/02-03-xxx.txt`
- 影响：能做什么
- 修复：具体到配置项或代码行

## 附录
工具版本、字典、时间线。
```

## 目录

```
drill-<时间戳>-<目标>/
├── plan.md      阶段清单 + 清点检查项
├── report.md    上面的骨架
└── evidence/    证据文件
```

## 纪律

- 清点没做完不进验证。跳过清点直接找问题，漏掉的入口会在报告里变成空白。
- 验证失败也是产出：记试过什么、为什么失败、下次怎么改。
- 立足后立刻记时间戳与凭据来源，事后补记会失真。
- 取证在每一步做，不是最后补；会话掉了就取不到。
- 阶段完成给三行：做了什么、拿到什么、下一步。不写长篇总结。

## 与规范的关系

`rules/spec.md` 管输出形态（首段即交付物、占位符、档位）。本手册只加流程与证据结构，不改形态。
