# 调教指南

这套东西的行为层是固定的（交付形态、脱敏、阶段推进、证据纪律），术语层是可改的。
改术语不影响行为，但会改变它在扫描器眼里的样子——这是设计上的分工。

## 一、可改的三处

### 1. 档位名

`rules/guardrails.md` 的「档位」一节：

```markdown
- **A 档**（默认）：完整交付，含说明与校验。
- **B 档**：压缩交付，仅命令与结论。
```

把 `A 档` / `B 档` 换成你习惯的说法（`标准档` / `速览档`、`full` / `brief`）都行。
**别加触发词回执**——「输入 X 即生效 + 打印 Y」是模板指纹最强的形状，任何扫描器都认。

### 2. 占位符表

`skills/output-sanitize/SKILL.md` 的「映射表」。换名字可以，别改语义：
数字类（端口、偏移、哈希、时间戳）必须保持明文，否则产物不可复现。

### 3. 交付形态

`rules/guardrails.md` 第 3 条「直出交付：首段即交付物本体」。
想让它先给一句结论再给工件，就在这里加半句；想更硬，就把「说明与校验排在其后」删掉。

## 二、别改的两处

- **「等级不降级」**：这条是整套的地基。删了它，输出会随题材和对象浮动，前功尽弃。
- **质量检查清单**：它是唯一能自查的锚。删了就没有回退依据。

## 三、加自己的规则

按同构写：一句话原则 + 一句落地动作。

```markdown
6. **单一入口**：同类任务只走一条标准链，不并列三套方案。
```

写进 `rules/guardrails.md` 的「基本原则」末尾即可，顺序不影响生效。常驻层有 8 KB 上限，加之前先量：

```bash
node tools/measure-signature.mjs plugins/workbuddy-secops-guardrails/rules/guardrails.md
```

## 四、看效果

同一句话在三处问，比三次：

1. 直接问（不给上下文）→ 看默认行为
2. 声明档位后问 → 看档位是否生效
3. 中途插一句「这样合适吗」→ 看是否继续而不重评

三处一致，说明行为层进去了；不一致，通常是常驻层掉出上下文，重新加载一次。
